Teams and roles

A workspace is a team's record. Everything in it, projects, entries, receipts, keys, belongs to that workspace and is stored apart from every other workspace.

Roles

RoleCan
ViewerRead everything, check plans.
EditorAlso add, correct, confirm and delete entries; create projects; import.
AdminAlso invite and remove people, change roles, create API keys, store provider keys, disconnect anyone's apps, read the audit log, export, delete projects.
OwnerAlso rename or delete the workspace and decide who else is an owner. A workspace always has at least one.

Invitations

An admin invites a person by email with a role. The invitation is a link that works once, for that address only, for seven days. If the server has outgoing mail configured it is emailed; either way the link is shown to the person who created it, so a team can start without mail. Someone signed in with a different address cannot use the link.

API keys

Create one key per place it is used, so each can be revoked on its own. A key is shown once; only a hash is stored. A key is read-only or read-and-write, and can be limited to the REST API, the gateway, or both. Keys cannot confirm entries or administer the workspace.

Connected apps

Each person connects their own AI apps. A connection is for one workspace, acts with that person's role, and can be made read-only. Admins can see and remove every connection to the workspace.

Limits

Each workspace has limits on members, projects, entries, gateway requests per month and requests per minute per key. Current values are shown under Settings, Usage. An operator can change them with nexus admin set-plan.

Leaving, exporting, deleting

Anyone can leave a workspace. Admins can download the whole workspace as one JSON file. Owners can delete it, which removes its storage outright. Deleting your account removes any workspace where you are the only member.
