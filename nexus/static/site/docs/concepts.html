Concepts

The record is a set of entries per project. Each entry is a claim with an author, a status and a history.

Entries

KindUse it for
DecisionSomething the team has settled. Agents are told to follow these.
Assumption, hypothesisSomething being relied on that is not proven.
Finding, evidenceSomething observed or measured.
QuestionSomething not yet answered. A decision can depend on one.
Objective, task, noteThe goal, work to do, and everything else.

An entry can carry a claim key and value, such as test.framework = vitest. Two active entries with the same key and different values are reported as a possible conflict.

How far an entry was checked

Shown asMeans
ConfirmedA signed-in person vouched for it as written. Programs and AI tools cannot do this.
Evidence-supportedAt least one source is attached. The source is not judged.
UnverifiedNobody has checked it. Everything an AI tool writes starts here.
Challenged, contradictedAnother entry disputes it.
Superseded, retracted, resolvedNo longer current. Kept as history.

Rewording a confirmed entry (its title, text, key or value) clears the confirmation, whoever does it. What was vouched for no longer exists.

Replacing instead of overwriting

A newer entry supersedes an older one. The old entry stays, marked as replaced and linked to its replacement. Every edit also keeps the previous version with who changed it and the reason they gave.

Review

The Review tab lists what needs a person: explicit contradictions, entries with the same key and different values, claims with no evidence, assumptions something depends on, decisions resting on an open question or a replaced entry. Each item names the entries it is based on and how sure it is: certain (a fact about the data), stated (someone recorded the conflict) or possible (a match that needs judgement).

The briefing

The text a model is handed when it does not ask through tools. It is small by design, with a size limit you set, and it is filled in a fixed order: decisions, unresolved conflicts, replaced entries, assumptions, open questions, findings. Each line carries the entry's number and how far it was checked. It is the same bytes for the same project state. You can restrict it to confirmed and evidence-supported entries.

Receipts

Each time a model is handed a project, a receipt records which entries it was given, at which version and status, to whom, through which way in, and a hash of the exact text. Opening a receipt later shows which of those entries have changed since.

The check

Compares planned steps with the record and reports three things separately: a conflict (same claim key, different value), resembles a replaced record (close in wording to something superseded or retracted), and related entries to read. It involves no AI model. See what it does not do.
