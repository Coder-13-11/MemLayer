Gateway

For tools that can change a base URL but cannot use connectors. The gateway forwards a request to the provider that speaks the same wire format, adds the project's briefing on the way, and writes a receipt.

It is deliberately not a router. It does not translate between formats, pick models, or resell access. You use your own provider keys and pay your provider directly.

Streaming responses are relayed byte for byte.

Two ways to supply the provider key

Stored

Store the provider key once under Settings, Provider keys. The tool sends only the {{BRAND_NAME}} key.

curl {{API_URL}}/chat/completions \
  -H "Authorization: Bearer nxk_..." \
  -H "x-nexus-project: Checkout rebuild" \
  -H "Content-Type: application/json" \
  -d '{"model": "your-model", "messages": [{"role": "user", "content": "Add tests for the cart"}]}'

Pass-through

Keep sending your own provider key as usual and add the {{BRAND_NAME}} key in a separate header. The provider key is forwarded untouched and is never stored or logged.

export ANTHROPIC_BASE_URL={{GATEWAY_URL}}
export ANTHROPIC_CUSTOM_HEADERS="x-nexus-key: nxk_...
x-nexus-project: Checkout rebuild"

Request headers

HeaderMeaning
x-nexus-projectProject name or id. Without it, the key's default project is used. With neither, nothing is added and the request is only metered.
x-nexus-contextall (default), confirmed (only confirmed or evidence-supported entries) or off.
x-nexus-context-budgetSize limit for the briefing in tokens. Default 1200, from 300 to 6000.
x-nexus-providerForce openai, anthropic, google, openai_compatible or mock. Otherwise chosen from the endpoint and the model name.
x-nexus-refresh: 1Rebuild the briefing now instead of waiting for it to expire.

Response headers

HeaderMeaning
x-nexus-receiptThe receipt for the briefing that was added.
x-nexus-context-recordsHow many entries it contained.
x-nexus-providerWhere the request was sent.

Where the briefing goes, and why it is held still

The briefing is added after your tool's own system text, never before it: as an extra system message for Chat Completions, a final system block for Messages, and appended to instructions for Responses. Your own cached prefix is not disturbed.

Once built for a project, the briefing is reused unchanged for 15 minutes, even if the record changes, so the start of the prompt stays identical and your provider's prompt cache keeps working. A new receipt is written each time it is rebuilt, not on every request.

What is kept

For each request: the time, key name, model name, provider, status code, token counts as reported by the provider, and the receipt number. Request and response text is not stored or logged.

The mock provider

Any model name starting with mock is answered inside {{BRAND_NAME}}, in all three formats, with a reply that says plainly no model was called. It exists for trying the gateway and for tests.

Tested against

The gateway's tests run against stand-in servers that speak each wire format, including streaming. It has not been run against live provider accounts as part of the test suite. If a provider changes its format, forwarding is unaffected but usage counts may read as zero.
